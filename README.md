# NavDat — бортовой комплекс

Бортовая программа сбора аэрогеофизических данных **NavDat** (ранее
поставлялась компанией «Геотехнологии» для Ubuntu 16.04) и её перенос на
**Ubuntu 24.04 LTS, x86-64**.

В репозитории лежат открытые части NavDat и всё, что нужно для установки на
новую Ubuntu. Сами программы `bortd` (бортовой демон с драйверами приборов)
и клиенты (`navdat-arrow`, `navdat-specview` и др.) закрытые: исходников нет,
есть только собранные под x86-64 deb-пакеты. Они хранятся отдельно, в
приватном репозитории (см. «Администратору»).

## Ограничения — прочитайте до установки

- **Только x86-64.** `bortd` и клиенты существуют только как программы для
  x86-64; пересобрать их под ARM (Raspberry Pi и т.п.) нельзя. Мастер
  установки на другой архитектуре сразу останавливается.
- **Проверено только на Ubuntu 24.04** (24.04.5, x86-64, в виртуальных
  машинах). Онлайн-мастер пускает и более новые версии, но на них ничего не
  проверялось. Офлайн-комплект ставится только на ту версию Ubuntu, для
  которой собран.
- **С реальными приборами не проверялось.** `bortd` и клиенты проверены
  только в демо-режиме `bortd` (без приборов): демон стартует, отвечает по
  протоколу, клиенты открывают окна. Подключение приборов, запись полёта и
  совпадение файлов данных со старой системой не проверялись. Перед работой
  в воздухе нужна наземная проверка на реальном ноутбуке с приборами.
- **Известные нерешённые проблемы** (найдены ревизией кода, не исправлены):
  клавиши яркости могут не работать на новых ноутбуках (используется
  `xbacklight`); панель индикаторов вверху экрана шириной 600 пикселей
  вмещает около 9 приборов; при зависании `bortd` окно настроек и апплет
  могут перестать отвечать.

## Содержимое

| Каталог | Содержимое |
|---|---|
| `bort/bortcfg/` | `navdat-bortcfg`: конфигуратор `bortd`, апплет в трее, сохранение и восстановление сессии. Python 3, GTK 3 (PyGObject) |
| `bort/applications`, `bort/menus`, `bort/desktop-directories` | Ярлыки и XDG-меню клиентов NavDat |
| `bort/glade/` | Интерфейсы закрытых клиентов `rapanel`, `tvpanel`, `rhost-koleso` (используются бинарниками) |
| `navdat/` | Справка (DocBook XML и HTML, ru/en) и `navdat-help` |
| `navdat-awesome-config/` | Рабочий стол оператора: конфигурация awesome WM, X-сеанс `navdat-awesome`, индикаторы приборов |
| `install/` | Мастер установки `navdat-install.sh` и сборщик офлайн-комплекта |
| `packaging/` | Сборка deb-пакетов и перепаковка закрытых пакетов для 24.04 |
| `tools/glade2builder.py` | Конвертер интерфейсов libglade → GtkBuilder |
| `tests/` | Тесты bortcfg с имитацией `bortd`; `tests/vm/` — проверки в виртуальных машинах |

Исходная версия для Ubuntu 16.04 — в ветке `main`.

## Что изменилось по сравнению с версией для 16.04

- **bortcfg** переписан на Python 3 и GTK 3. Последовательные порты ищутся
  по `/dev` (HAL из Ubuntu давно удалён).
- **On-Board Server (FE)** в bortcfg по умолчанию работает на локальном
  сокете, как в штатном конфиге. Если выбрать TCP, `bortd` перестаёт
  принимать клиентов на этом компьютере (так устроен сам `bortd`, проверено),
  поэтому TCP стоит выбирать, только если это действительно нужно.
- **Рабочий стол**: awesome 4.3 со своим X-сеансом вместо Unity и
  gnome-session; picom вместо compton, `dm-tool lock` вместо
  gnome-screensaver, `pactl` вместо `pacmd` (работает с PipeWire).
- **Индикаторы приборов** вверху экрана строятся из `~/.bort/bortdrc` и
  показывают состояние подключений самого `bortd`. К приборам они не
  подключаются и ничего им не отправляют (старая версия сама подключалась к
  приборам и могла портить данные).
- **bortd** работает на 24.04 без изменений (ему нужны только glibc и
  libstdc++); в пакете исправлена зависимость `libgcc1` → `libgcc-s1`.
- **Клиенты** запускаются без контейнера. 15 из 21 обходятся библиотеками
  самой Ubuntu 24.04 (в основном GTK2 и libglade). Остальным пакет `navdat-compat` кладёт в
  `/opt/navdat/lib` библиотеки из Ubuntu 16.04 (Qt4, Qwt, libpng12, libaudio,
  libFOX); `/usr/bin/navdat-*` — обёртки, которые их подключают.
- **Пользователь `navdat`** создаётся без пароля; мастер установки задаёт
  пароль, который вводит человек. Стандартного пароля больше нет.

## Установка на новый ноутбук

Нужен ноутбук x86-64 с Ubuntu 24.04. Есть два способа: онлайн (нужен
интернет и ключ доступа) и офлайн-комплект (интернет не нужен).

### Онлайн

Скачать мастер и запустить его под своей учётной записью (с правами
администратора):

```bash
wget https://raw.githubusercontent.com/petrowmaxic/navdat-bort/port/ubuntu-24.04/install/navdat-install.sh
```

```bash
bash navdat-install.sh
```

Мастер по очереди спросит:

1. логин GitHub и ключ доступа к закрытым пакетам NavDat (выдаёт администратор);
2. новый пароль для оператора `navdat`, дважды;
3. входить ли автоматически при включении;
4. пароль администратора этого ноутбука.

Дальше он сам скачивает закрытые пакеты и исходники, собирает и ставит всё,
создаёт пользователя `navdat`, делает LightDM менеджером входа и предлагает
перезагрузку. Журнал — `~/navdat-install.log`; ключ доступа и пароли в него
не пишутся.

Мастер скачивает исходники с ветки `port/ubuntu-24.04` в момент установки,
то есть ставит её текущее состояние.

### Офлайн-комплект (без интернета)

Комплект — один архив (около 550 МБ, около 1200 пакетов): мастер, все
пакеты NavDat, включая закрытые, и все нужные пакеты Ubuntu 24.04 вместе с
зависимостями. Его собирают там, где есть интернет, и переносят на флешке.

Готовый архив лежит в приватном релизе
[`offline-24.04`](https://github.com/petrowmaxic/navdat-bort-private/releases/tag/offline-24.04).
Он собран 15.10.2026 из коммита `66c15fe` (с исправлениями ревизии кода),
SHA256 `4fcd1e1457537afcf098d433def0baebb1082b8f6e6ea7ff19bf46fe1cff1a04`.
После изменений в ветке комплект нужно пересобрать: архив сам не обновляется.

Собирать на Ubuntu 24.04 x86-64 с интернетом, из каталога с оригинальными
deb NavDat:

```bash
sudo install/build-offline-bundle.sh ~/navdat-debs ~/navdat-bundle
```

Получится `~/navdat-bundle/navdat-offline-24.04-amd64.tar`. На ноутбуке:

```bash
tar -xf navdat-offline-24.04-amd64.tar
```

```bash
bash navdat-offline-24.04-amd64/navdat-install.sh
```

Мастер видит комплект рядом с собой и работает без сети. Он спросит пароль
оператора, автовход и пароль администратора. Пакеты ставятся только из
комплекта, системные источники apt не меняются.

### Администратору

Закрытые пакеты хранятся в приватном репозитории
`petrowmaxic/navdat-bort-private`:

- релиз [`navdat-0.2.12`](https://github.com/petrowmaxic/navdat-bort-private/releases/tag/navdat-0.2.12)
  — оригинальные закрытые пакеты для онлайн-мастера;
- релиз [`offline-24.04`](https://github.com/petrowmaxic/navdat-bort-private/releases/tag/offline-24.04)
  — офлайн-комплект (из какого коммита собран — см. выше).

Если понадобится создать релиз с пакетами заново, из каталога с
оригинальными deb (`bortNFVSEGEI/bortNFVSEGEI`):

```bash
cd bortNFVSEGEI/bortNFVSEGEI && shasum -a 256 navdat-bortd_*.deb navdat-clients-*.deb navdat-full_*.deb libfox-gt_*.deb > SHA256SUMS
```

```bash
gh release create navdat-0.2.12 --repo petrowmaxic/navdat-bort-private --title "NavDat 0.2.12" --notes "Оригинальные пакеты для navdat-install.sh" navdat-bortd_*.deb navdat-clients-*.deb navdat-full_*.deb libfox-gt_*.deb SHA256SUMS
```

В релиз кладутся только нужные мастеру пакеты. Оригинальные `navdat-user`
(в нём зашит стандартный пароль оператора), `navdat-help` и `awesome` не
нужны: вместо них ставятся пакеты из этого репозитория.

Ключ доступа для онлайн-установки: GitHub → Settings → Developer settings →
Personal access tokens → Fine-grained tokens → Generate new token.

- Repository access: только `petrowmaxic/navdat-bort-private`.
- Permissions → Contents: Read-only.
- Срок действия — по вашей политике.

Оператору сообщаются логин учётной записи, создавшей ключ, и сам ключ.
Для офлайн-комплекта ключ не нужен.

### Вручную, без мастера

```bash
packaging/build-debs.sh dist
```

```bash
packaging/repack-proprietary.sh ~/navdat-debs dist
```

```bash
sudo apt install ./dist/*.deb
```

```bash
sudo passwd navdat
```

`repack-proprietary.sh` скачивает из архива Ubuntu 16.04 библиотеки для
`navdat-compat` (версии и SHA256 зафиксированы в `packaging/build-compat.sh`).
В версию каждого собранного пакета добавляется время сборки, поэтому новая
сборка ставится поверх старой.

## Что и как проверено

Все проверки — в виртуальных машинах (QEMU), на реальных ноутбуках и с
реальными приборами ничего не проверялось.

**Закрытые программы проверены только на x86-64.** На Mac с процессором
Apple (ARM) x86-64 ВМ работает через эмуляцию и медленно. Быстрая проверка
`tests/vm/run.sh` без параметров запускает ВМ той же архитектуры, что и
компьютер, — на ARM-Mac это arm64. В ней проверяются только открытые части
(bortcfg, рабочий стол, индикаторы, сборка пакетов), а `bortd` заменён пустой
заглушкой. То, что эта проверка проходит на arm64, **не означает**, что
NavDat работает на ARM.

| Проверка | Команда | Что проверяет |
|---|---|---|
| Открытые части | `tests/vm/run.sh` | юнит-тесты bortcfg, сборка и установка пакетов, сеанс `navdat-awesome`, меню, bortcfg, индикаторы (с заглушкой `bortd`) |
| Закрытые программы | `VM_ARCH=amd64 NAVDAT_DEBS=~/navdat-debs tests/vm/run.sh` | то же на x86-64 плюс настоящий `bortd` в демо-режиме со всеми типами приборов и запуск каждого клиента из меню |
| Онлайн-мастер | `VM_ARCH=amd64 NAVDAT_DEBS=~/navdat-debs tests/vm/run.sh install` | чистая ВМ, ответы как у человека, имитация GitHub (`tests/vm/fake_github.py`), перезагрузка, автовход оператора |
| Сборка комплекта | `VM_ARCH=amd64 NAVDAT_DEBS=~/navdat-debs tests/vm/run.sh bundle` | сборка офлайн-комплекта |
| Офлайн-установка | `VM_ARCH=amd64 NAVDAT_BUNDLE_TAR=<архив> VM_DIR=~/.cache/navdat-vm-offline tests/vm/run.sh offline-install` | чистая ВМ без интернета, комплект «с флешки», перезагрузка, автовход |

Результаты (15.10.2026, Ubuntu 24.04.5):

- **Закрытые программы, x86-64**: `bortd` 0.2.12 стартует в демо-режиме
  (525 переменных), отвечает по протоколу и останавливается по команде; все
  17 графических клиентов открывают окна, включая Qt4-клиенты и `fplan`.
  Прогон был до исправлений ревизии кода и после них не повторялся.
- **Онлайн-мастер, x86-64**: прошёл после исправлений ревизии.
- **Офлайн-установка, x86-64**: комплект из `66c15fe` (после исправлений
  ревизии) поставлен на чистую ВМ без доступа в интернет, после перезагрузки
  оператор вошёл автоматически. В той же ВМ `bortd` из комплекта запущен так
  же, как кнопкой Start в bortcfg: демон работает в демо-режиме, пишет
  журнал в `~/.bort/bortd.log` и останавливается по команде. Отдельно
  проверен отказ ставить комплект на другую версию Ubuntu.
- **Открытые части, arm64**: прошли после исправлений ревизии.
- **Не проверялось**: реальные приборы и запись данных; Ubuntu новее 24.04;
  клиенты на реальных экранах и видеокартах; клиенты, установленные из
  офлайн-комплекта (их запуск проверялся только при установке из пакетов, до
  исправлений ревизии).

CI (`.github/workflows/ubuntu-24.04.yml`, Ubuntu 24.04 x86-64) на каждом
коммите гоняет юнит-тесты bortcfg под Xvfb (протокол с имитацией `bortd`,
все диалоги устройств, сохранение конфига, апплет), собирает и ставит
открытые пакеты и запускает awesome с конфигом. Закрытые пакеты, мастер
установки и офлайн-комплект в CI не проверяются.
